\section*{Summary}

The frontend and backend are connected for most application data flows. The main mismatch is the login flow: the frontend calls \texttt{/api/auth/login}, but the Django route list does not define that endpoint. All other major endpoints reviewed in the frontend are present in the backend router and match the expected URL patterns.

\section*{Endpoint contracts}

\begin{itemize}[leftmargin=1.5em, itemsep=0.55em]

\item \textbf{GET /api/health/}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: \texttt{api.views.health}
    \item Frontend: used by account, settings, and chat health checks.
    \item Status: connected and active.
  \end{itemize}

\item \textbf{GET /api/environment/alerts/}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: \texttt{api.views.alerts}
    \item Frontend: called from \texttt{Alerts.jsx} with a point parameter.
    \item Status: connected and used for environmental alerts.
  \end{itemize}

\item \textbf{GET /api/environment/water/}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: \texttt{api.views.water}
    \item Frontend: used by \texttt{WaterStation.jsx} and \texttt{WaterStationPicker.jsx}.
    \item Status: connected and used for USGS water monitoring data.
  \end{itemize}

\item \textbf{GET /api/environment/fires/}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: \texttt{api.views.fires}
    \item Frontend: no direct fetch found in the reviewed frontend files.
    \item Status: backend route exists, but the current UI does not appear to call it directly.
  \end{itemize}

\item \textbf{GET /api/state-map/}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]

  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: \texttt{rag.views.status}

\item \textbf{POST /api/auth/login}
  \begin{itemize}[leftmargin=1.5em, itemsep=0.2em]
    \item Backend: not present in \texttt{backend/api/urls.py}
    \item Frontend: default value in \texttt{Login/login.jsx}.
    \item Status: not connected. This is the main missing backend contract.
  \end{itemize}

\end{itemize}

\section*{Key conclusions}

\begin{itemize}[leftmargin=1.5em, itemsep=0.5em]
\item Most frontend pages use the same backend routes that are defined in the Django router.
\item The field, gear, environment, crop, and account workflows are wired together correctly.
\item The login page is the only clear mismatch: the UI expects an authentication route that is not implemented in the backend.
\end{itemize}
